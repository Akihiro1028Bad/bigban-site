# タスク: 週次モードの実行
`docs/operations/growth-weekly-runbook.md` の「週次モード」セクションを読み、その手順どおりに**実データ・実 Notion DB**に対して実行してください。

## 手順の要点
1. `npm run growth:fetch` を実行し、`data/snapshots/<実行日>.json` を読む(対象週は自動=直近の確定週)。`errors` が空でないソースは推測で埋めず、その旨を明記。
2. **既存行の確定取得(必須・推測禁止)**: `npm run growth:existing` を実行し、その出力を**唯一のグラウンドトゥルース**として扱う。これは Notion の 3 DB を REST で実照会した結果(対象週レポートの作成済み/未作成、施策提案・記事ネタ案の全行と却下理由・検証結果)。
   - **冪等性は MCP やタイムスタンプで推測しない。** 必ずこの出力で判断する。
   - 「週次グロースレポート: 未作成」と出たら、**重複ではないので手順4のレポートを必ず新規作成する**(スキップ禁止)。「作成済み」のときだけレポート作成を省く。
   - 学習ループ: この出力に含まれる却下/見送りの判断者メモ・検証結果を読み、効かなかった方向・オーナーが嫌う方向は繰り返さない。
3. マーケターチーム: Task ツールでサブエージェントを**並列起動**し、SEO / ローカル(MEO) / CRO / ブランドの4視点で、6カテゴリ(コンテンツ / MEO / サイトデザイン / サイト表示内容 / 追加機能 / イベント)を分析。外部文脈は Web 検索で3層(地域・東京/全国・世界)を確認。
4. 週次レポートを Notion DB「週次グロースレポート」(data source `27d6794f-4133-4cd4-9407-491d95c1b82b`)に1ページ作成(今週の数字+優先上位+論点+データ注意)。
5. 施策登録:
   - コンテンツ → 「記事ネタ案」DB(`5adab8b1-f182-4123-b963-9463a2580d4a`)に ステータス=提案中。各案には タイトル案・概要・優先度・**根拠**(なぜこの記事か=数字/クエリ名) に加え、**構成案**(見出しアウトライン: 導入→H2/H3→CTA を箇条書き)を「構成案」プロパティに記載する(承認画面で記事の中身を把握できるようにするため)。
     - **狙い目テーマ(市場の空白・優先的に提案)**: 競合調査では「市川/本八幡/千葉 × 屋内」の読み物がほぼ無競合だった。次の手薄な領域を優先する: ①ローカル一次体験(本八幡で始める/体験ルポ) ②屋内施設の体験価値(全天候・夜可・空調) ③始めた後の継続・上達・仲間づくり(市場が「入門」で止まっている) ④ラケット競技(テニス/卓球/バド)経験者の移行ガイド ⑤シニアの健康(施設の実体験ベース・効果は断定しない=§5) ⑥一人参加の不安解消 / 法人・昼活利用。土台(cornerstone)になる総合ガイドは §2 のとおり長め(3,000〜5,000字)で。
   - その他5カテゴリ → 「施策提案」DB(`3503f4bc-b1c4-4927-91ce-7609a6c4e460`)に ステータス=未処理、週キー(例 `2026-W24`)・施策ID(例 `2026-W24-MEO-01`)付き
   - **重複防止**: 手順2の `growth:existing` 出力に載っている行のみを既存とみなす。同一週キー・同一施策名・既出・却下済みだけを再作成しない(出力に無いものは未作成なので作成する)。先週以前で未処理のまま残った行は見送りに更新。
6. 各カテゴリ最大5件・**質が量に優先**(根拠の薄い施策は出さない。無ければ少数でよい)。
7. **やらないこと**: 記事下書き/仕様書の作成(他モード)、microCMS 操作、git push、本番公開。

## 制約・参照
- 文体・地理スコープ(コア=市川・本八幡/準コア=東京東部・総武/都営新宿線/全国)は `docs/operations/growth-article-style.md` を参照。
- Notion のツール名は環境により異なる(headless では `mcp__claude_ai_Notion__*`)。data source ID は上記の固定値を使う。
- 最後に**完了報告**を出力: 作成した週次レポートの URL、登録した施策の件数(DB別・カテゴリ別内訳)、重複でスキップした件数。
