# 記事ネタ案作成ルール(shared)

このファイルは、Notion「記事ネタ案」DB に記事候補を作るときの共通ルールです。`weekly.md` の週次提案と、`initiatives.md` のコンテンツ施策→記事候補化は、どちらもこのルールに従います。本文下書きは作りません。本文下書きは、記事タブで承認された後に `draft-research.md` と `draft-write.md` が独立して担当します。

## 書き込み先

- data source: `記事ネタ案` = `5adab8b1-f182-4123-b963-9463a2580d4a`
- 新規作成時の `ステータス`: `提案中`
- `タイトル案` / `概要` / `優先度` / `根拠` / `構成案` は、承認画面で判断できる粒度で必ず書く
- 既存行の重複確認は、実行モード側が `npm run growth:existing` の出力を唯一のグラウンドトゥルースとして行う

## 媒体

任意 select プロパティ `媒体` がある場合は、次のいずれかを書く。プロパティ未追加なら欠落耐性で動くため、作成自体は止めない。

- `コラム`: SEO 資産になる検索流入向けの読み物
- `ニュース`: 告知、イベント、キャンペーン、施設更新の確定告知、事後レポート

### コラム

- 「本命1件＋補欠1件＋探索1件」を基本にする
- 成功仮説が弱い案、根拠が薄い案、検索意図が既存記事と実質同じ案は出さない
- 公開済み記事の成績サマリは、成功率・判定済み母数・未判定率・観測条件をセットで読む。成功本数だけで型を優先せず、判定済み3本未満は探索中とする
- 探索枠は探索中の型に同型の生きている記事案・観測中記事がない場合だけ使う。未判定率が高ければ判定待ちを優先し、適切な探索仮説がなければ枠を埋めない

### コールドスタート実験

公開済み記事がなく成功型を学習できない期間は、通常の本命・補欠とは別に**コールドスタート実験を最大1件**作ってよい。これは週次モードだけの例外であり、コンテンツ施策からの通常変換には適用しない。

- 根拠は `growth:fetch` の **GSC実データ**に限定し、対象クエリと impressions / clicks / CTR / position の実値を最低1組書く。外部トレンドだけでは実験枠にしない
- 市場の空白と施設の確定した強みが接続し、記事から予約意図までの仮説が立つテーマだけにする
- `根拠` の先頭へ識別子 **`【コールドスタート実験】`** を必ず付ける。新しいDBプロパティは増やさない
- `成功指標` は**公開28日**で判定できる具体的なGSC/GA4指標とする。想定CTAと記事→予約ページ到達の観測方法も書く
- 実験記事が提案中・承認済み・下書き・公開後未判定の間は、次のコールドスタート実験を出さない
- 公開28日の `公開後判定` が確定するまで、その実験記事からの派生案を出さない
- 成功なら実際に反応した隣接クエリ・読者状況へ派生できる。様子見なら改稿または観測延長を優先し、要改稿なら同方向を増やさない

### ニュース

- 確定した日時・内容のある告知だけを出す
- 未確定の日時、料金、所要分など `scripts/growth/facility-context.json` の doNotWrite に反する断定はしない
- 公式に公表・確定済みの日時(PR TIMES、公式SNS、Notion 行に確定記載があるもの)は書いてよい
- ニュースはコラムの「本命1件＋補欠1件＋探索1件」枠を消費しない

## 記事仮説プロパティ

コラム案には、公開後に成功/様子見/要改稿を判断できる仮説を必ず付ける。仮説が立てられない記事案は作らない。

- `記事タイプ`(select): `獲得` / `不安解消` / `資産` / `比較` / `イベント` のいずれか
- `狙う読者`(text): 誰の、どんな状況か
- `検索意図`(text): その読者が打つ検索と知りたいこと
- `勝ち筋`(text): なぜこの記事が勝てるか。市場の空白と施設の強みで書く
- `想定CTA`(multi_select): `Instagram` / `LINE` / `予約` / `アクセス` / `価格` / `問い合わせ` から該当を選ぶ
- `成功指標`(text): 公開28日で見る判定基準

ニュース案は SEO 系の `検索意図` / `勝ち筋` を無理に付けない。代わりに、告知としての `狙う読者`、`想定CTA`、`成功指標` を書く。告知種別は当面 `記事タイプ=イベント` に寄せてよい。

## 構成案の書式

`構成案` は、各セクションを「`## 見出し`」の行と、その直後の1行説明で表す。セクション間は空行で区切る。承認画面はこの書式をセクション単位でパースして表示する。

```md
## 市川でできる場所は3つ
屋外コート・体育館・屋内専用の違いを公平に整理する

## 屋内専用という選び方
天候に左右されない利点を具体例で書く
```

- 見出しは `#` で始める。通常は `##`
- 説明は1行で簡潔にする。難しければ見出しのみでもよい
- タイトル盛り、未確定情報の断定、AI っぽい大げさな言い回しは避ける
- 本文画像を想定する場合は、該当セクションに `[画像:<スタイル>: <説明>]` または `[画像:<スタイル>: <説明> | 文字: <textSpec>]` を入れる

## カニバリ回避

- `growth:existing` 出力の「検索意図インデックス」を読み、実質同一の検索意図のネタは出さない
- 似た意図でも、読者・状況・切り口が違い、その差分を `勝ち筋` に書ける場合だけ提案してよい
- `growth:existing` 出力の「カバレッジ集計」で薄い型や媒体を確認してよいが、薄い枠を埋めるためだけの量産はしない。サマリの公開0本の既知型はゼロサンプルの探索候補として扱う

## 優先テーマ

市場の空白と施設の強みが接続できるものを優先する。

- ローカル一次体験: 本八幡で始める、体験ルポ
- 屋内施設の体験価値: 全天候、夜可、空調
- 始めた後の継続、上達、仲間づくり
- テニス、卓球、バドミントン経験者の移行ガイド
- シニアの健康。ただし効果は断定せず、施設の実体験ベースで書く
- 一人参加の不安解消
- 法人、昼活利用
- 土台になる総合ガイドは `docs/operations/growth-article-style.md` §2 に従い、必要なら長めにする

## コンテンツ施策から記事候補化する場合

`initiatives.md` が `カテゴリ=コンテンツ` の施策を記事ネタ案へ変換する場合も、上記と同じプロパティ・同じ構成案書式で作る。

- 施策名をそのままタイトルにしない。施策の狙いを読み、記事として自然な `タイトル案` にする
- 施策の `根拠` / `想定アクション` / `仮説` / `成功指標` があれば、記事案の `根拠` / `概要` / `勝ち筋` / `成功指標` に反映する
- 記事候補ページの本文には、元施策ページへの参照と、変換した理由を短く残す
- 元施策は `成果物化済` に更新し、`成果物リンク` には作成した記事ネタ案ページ URL を記録する
