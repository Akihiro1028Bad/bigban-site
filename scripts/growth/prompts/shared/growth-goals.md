# グロース目標・週次分析基準

このファイルは、週次分析が数字の増減だけで施策を量産せず、事業目標から逆算するための共通基準です。データ取得方法や Notion DB スキーマは変更しません。

## 目標

- 最重要目標: コート予約率とコート稼働率の向上
- 中間指標: 予約ページ到達、予約 CTA、指名検索、GBP アクション、LINE 友だち追加
- 継続指標: 再予約、イベント再参加、リピート率
- 長期目標: 日本一のピックルボールコート

「日本一」は広告上の断定ではなく、次の評価軸を継続的に改善する長期目標として扱う。

1. 予約稼働
2. 顧客評価と口コミ
3. 施設体験と継続利用
4. 地域・全国での認知
5. コミュニティとイベント

全国の施設と比較できる同条件のデータがなければ、日本一と判定しない。週次レポートでは評価軸ごとに `確認可能` / `未計測` / `比較データ不足` を明記する。

## 予約ファネル

分析順序は固定する。

`認知 → 興味 → 予約意図 → 予約完了 → コート稼働 → 再予約・継続`

| 段階 | 主な確認材料 |
|---|---|
| 認知 | GSC 表示・順位・指名検索、GBP、SNS、外部露出 |
| 興味 | セッション、ランディングページ、記事閲覧、エンゲージメント |
| 予約意図 | `reservation_click` + `reserve_entry_click`（代理指標） |
| 予約完了 | freshな予約CSVの実予約数、または同週のオーナー手入力 |
| コート稼働 | 予約済みコート枠、販売可能コート枠、時間帯別稼働 |
| 再予約・継続 | 再予約、イベント再参加、リピート利用 |

## 指標の呼び分け

- `コート予約率 = 予約済みコート枠 ÷ 販売可能コート枠`
- `予約転換率 = 予約完了数 ÷ 予約ページ訪問数`
- 予約意図率 = `/reserve` 到達数 ÷ サイト訪問数

分子と分母がそろわない指標は計算しない。予約 CTA を、予約完了・コート予約率と呼ばない。実予約データが欠損または7日超で古い場合だけ、記事別予約意図を代理指標として使い、その旨をレポートと提案の成功指標に明記する。LINE・Instagram・その他CTAは別成果であり、実予約や予約意図へ加算しない。GA4のkeyEvents合計を予約数とみなさない。

## ボトルネック分析

1. 欠損・取得失敗・計測期間・サンプル不足を先に確認する。
2. ファネル各段階について、確認できる事実、確認できない事実、前週・4週トレンドを整理する。
3. 事業目標への影響が大きく、データで説明できるボトルネックを最大3件に絞る。
4. 各ボトルネックに原因仮説と反証材料を付ける。反証材料が強い仮説は採用しない。
5. データ不足そのものが重要なら、集客施策ではなく計測改善を提案する。

## 提案品質ゲート

施策・記事案は、次をすべて説明できる場合だけ登録する。

- 対象ファネル
- 解消するボトルネック
- 予約率、予約意図、稼働、継続のどれにどう影響するか
- 根拠となる数値、クエリ、過去の検証結果、または外部需要
- 成功指標と検証予定日
- 確度と、その確度にした理由
- 人間が次に行う具体的なアクション

記事案は、検索・記事コンテンツが特定したボトルネックの解消に有効な場合だけ作る。SEO 流入だけが増えても予約ファネルへの接続を説明できない案は出さない。本命1件と補欠2件を基本上限とし、弱い案で枠を埋めない。
