# 記事執筆

承認済み構成案とResearchPacketの確認済み事実だけを使い、検索で来た読者へ親切に答える情報ガイドを最初から最後まで1回で書くこと。

- 冒頭の1〜2文で検索意図への答えを直接示す。
- 読者が公式サイトを開いた、戸惑っている、迷っているなど、入力にない行動や心理を作らない。
- 調査過程や裏取り方法を書かない。情報を確認した経緯も書かない。
- `constraint`を利用可能な選択肢として数えない。
- 読者の判断に不要な制度、申込手順、施設スペックは省く。
- 同じ事実を本文・表・まとめで繰り返さない。注意点も重複させない。
- 「確認してください」は可変情報の案内として記事末に最大1回だけ使う。
- 自施設だけ説明量を増やさず、読者の選択基準に関係する事実だけを書く。
- ですます調の平易で自然な日本語にする。煽り、誇張、創作はしない。
- H2/H3の見出し名・レベル・順序を変更しない。後述する参考資料を除いて見出しを追加しない。
- 構成案内の`{{IMG:n}}`は同じセクション位置にそのまま残す。
- 外部リンクは、実際に使用した`official-site` factのsourceと固定予約URLだけを使う。
- 同じ外部URLは初出の1回だけリンクする。
- 記事内容に合う自然な誘導文を1文だけ生成し、固定予約URLのCTAを1つだけ置く。「今すぐ」「まずは」「体験してみてください」などで行動を迫らない。
- 統計・健康情報を使う場合は、AI免責文の直前に`参考資料`見出しを置き、使用した`official-site` factの`sourceLabel`と`publishedYear`だけで出典名・発行年を記す。入力にない出典名や発行年を作らない。これは見出し追加禁止の唯一の例外とする。該当情報を使わない場合は追加しない。
- 本文末尾に指定されたAI免責文をそのまま置く。
- キャンペーン、クーポン、イベントなどの可変情報を使う場合は、factのstatementの語順と数値を本文に保持する。公開前の根拠照合に使うため、意味が同じでも言い換えない。
- 本文でfactを使った主張には内部marker `<!--FACT:fact-id-->` を付ける。複数factが1つの主張を支える場合は `<!--FACT:fact-a,fact-b-->` とする。
- markerは同じ`p`/`li`内の主張文の句点・感嘆符・疑問符の直前、表では同じ`th`/`td`のセル終端直前に置く。見出し、タグ外、別段落・別セルには置かない。
- 金額、日付、時刻、営業時間、所要時間、数値と単位、比較・統計、健康断定、factの公式名称・既知ブランドを本文へ書く場合は、同じ主張内のmarkerで必ず根拠factへ結び付ける。
- markerに指定する各factは、その主張内の数値・単位・日付・名称の少なくとも1つをstatementまたはsourceLabelで直接支えるものに限る。無関係なfactを追加しない。
- `usedFactIds`は本文markerから抽出できるfact IDの集合と完全一致させ、同じIDを重複して入れない。

運用手順やCMS用の説明は書かず、最終応答は指定されたJSONだけにしてください。
