# クラウドルーチン セットアップ手順(オーナー作業)

> 対象: claude.ai のルーチン(scheduled cloud agents)で日次ウォッチ・週次ドライバーを動かすための初期設定。
> 設計: `docs/superpowers/specs/2026-08-05-growth-copilot-design.md` §9
> この作業は**オーナー本人が行う**。AI に値を渡す必要はないし、渡してはいけない。

## ① 環境変数(env secrets)を5つ登録する

claude.ai の設定 → 環境変数(Environment variables / Secrets)に、以下の5つを登録する。
**値は自宅 Mac のリポジトリ `/Users/…/dev/bigban/.env.local` に既にあるものをそのままコピーする。**
(このファイルは `.gitignore` 済みでリポジトリには入っていない)

| キー | 中身 |
|---|---|
| `GROWTH_GOOGLE_CLIENT_ID` | 分析用 Google OAuth クライアント ID |
| `GROWTH_GOOGLE_CLIENT_SECRET` | 同 クライアントシークレット |
| `GROWTH_GOOGLE_REFRESH_TOKEN` | 同 リフレッシュトークン(**読み取り専用スコープ**) |
| `GROWTH_GA4_PROPERTY_ID` | GA4 プロパティ ID |
| `GROWTH_GSC_SITE_URL` | Search Console のサイト URL |

- キー名は**1文字も変えない**(スクリプトが名前で参照している)。
- 値の前後に空白・引用符を入れない。`.env.local` の `=` の右側だけをコピーする。
- 貼り付けたら、この手順書やチャットに値を貼り戻さない。**登録作業そのものが利用の了解**として扱われる。

**補足**: `query.mjs` は `.env.local` が無い環境では自動的に環境変数(env secrets)へフォールバックする(2026-08-05 対応済み)。
初回実行で数字なし版が届いたら、secrets のキー名・値の貼り付けミスを疑う(→ ③)。

Notion(施策台帳・記事ネタ案・Labola 台帳)は**コネクタ接続**なので env 設定は不要。
microCMS・画像生成 CLI・LINE はローカル専用のまま使わない。

## ② ルーチンの一時停止・再開・削除

claude.ai のルーチン一覧(Automations / Routines)から操作する。

- **一時停止**: 対象ルーチンを開き、有効/無効のトグルをオフにする。設定と履歴は残るので、旅行・繁忙期などで通知を止めたいときはこれ。
- **再開**: 同じトグルをオンに戻す。停止中に発生した分は遡って実行されない(その週の分析は対話で手動実行 → `docs/operations/interactive-analysis-runbook.md`)。
- **削除**: 一覧から削除。プロンプト本文は `docs/growth/routines/` に残っているので、消しても同じ内容で作り直せる。
- **スケジュール変更**: 日次ウォッチ 毎朝 09:00 / モーニングブリーフ 毎朝 08:00 / 週次ドライバー 木曜 08:00 が現行設定。変える場合は設計書と `docs/growth/README.md` の時刻表記も合わせて直す。
- **届き方の正常状態**: モーニングブリーフは**毎朝必ず届く**・日次ウォッチは**沈黙が正常**・週次は木曜に必ず届く。この非対称を覚えておくと「壊れているのか正常なのか」で迷わない。

止めてよい判断基準: **通知が多すぎて読まなくなったら止める。** 読まれない通知は害。
特に日次ウォッチは「平常時は完全沈黙」が正常動作なので、毎日届くようなら閾値がおかしい。

## ③ トラブル時の確認順

上から順に確認する。1つ潰すごとに次の実行を待つ。

1. **「数字なし版」ダイジェストが届いた** → GA4/GSC が読めていない。
   env secrets 5つの名前・値・貼り付けミス(空白/引用符)を確認。①の補足も確認する。
   なお、数字なし版が届くのは**設計どおりのフォールバック**であり、沈黙より正しい挙動。
2. **メッセージが1通も届かない** → ルーチンが無効化されていないか、スケジュールが意図どおりか確認。
   日次ウォッチの沈黙は正常。生存確認は **claude.ai のルーチン一覧の実行履歴(最終実行日時)** で行う(週次ダイジェストは日次の生存を証明できない)。
3. **台帳・施策台帳の情報だけ欠ける** → Notion コネクタの接続と共有範囲を確認する。
4. **draft PR が作られない/作られすぎる** → 許可リスト外(新規ページ・依存追加・env・API・公開系・microCMS)に触ろうとして止まった可能性。
   ブランチ `growth/*`・PR タイトル `proposal:`・**draft のまま**が守られているかを見る。マージは必ず人間。
5. **判定や提案の中身がおかしい** → `docs/growth/playbook.md` と `docs/growth/seasonal.md` が最新か確認する。
   ルーチンはこの2ファイルを読んで判断するので、古い学びが残っていると同じ負け筋を再提案する。

解決しない場合は、届いたメッセージをそのまま対話セッションに貼って「これが出た。原因を切り分けて」と頼むのが早い。
