# 計測の修理 手順書(オーナーが行う設定)

issue #505 の設定側の手順。コードでは触れない外部サービスの設定をまとめる。
設計: `docs/superpowers/specs/2026-10-01-szb-505-measurement-design.md`

## 0. 先に確認すること

- [ ] **Vercel のダッシュボードで Speed Insights を有効にしてから、本番に出す。** 有効にするまでは `/_vercel/speed-insights/script.js` が 404 になる(画面は壊れないが、コンソールにエラーが出る)。
- [ ] **Vercel のプランで Speed Insights が使えるか。** Vercel のダッシュボードで対象プロジェクトの「Speed Insights」タブを開き、有効化できるか確認する。
  - 使える → 「Enable」を押す。数日たつとページ単位の実ユーザー値(p75)がダッシュボードに出る。
  - 使えない(有料機能) → コードに入れた `<SpeedInsights />` はデータが送られないだけで、画面には何も起きない。表示速度は下の「3. PSI API キー」の CrUX 取得だけで運用する。
- **プレビュー環境のアクセスも、Speed Insights の計測の枠(データポイント)を使う。** プレビューを開いた分も数に入るので、枠が気になるときは本番だけを有効にするか、プレビューの確認を必要な分だけにする。

## 1. GA4 管理画面の設定

GA4 のプロパティの管理画面で行う。**設定は過去のデータには効かない**(設定した日から)。過去分を除いて見たいときは、`node scripts/analytics/query.mjs` の「LaBOLA 段別」が自動アクセスを除いた値を出す。

### 1-1. 自動アクセスの除外

- 事実: 2026-09-16 から LaBOLA のカレンダー(`/r/shop/3473/calendar/` 系)に、画面 800x600・Linux の巡回が1日約100〜130ユーザー来ている。自社の処理ではなく第三者の巡回とみている(V 調査 2026-09-30)。LaBOLA の週カレンダー閲覧者の約4割がこれで、LaBOLA 側の段の分母を水増ししている。
- [ ] 管理 → データの設定 → データフィルタ → 「フィルタを作成」。
  - 画面解像度が `800x600` **かつ** オペレーティングシステムが `Linux` のイベントを除外する条件が組めるかを確認する(単独条件だと実ユーザーを巻き込む)。
  - フィルタの状態は最初「テスト」にして、数日レポートで確認してから「有効」にする。
- [ ] 組めない場合は、GA4 を変えずに、集計スクリプト側の除外だけで運用する(`query.mjs` の LaBOLA 段別と、基準値の判断はこれで足りる)。その場合は司令塔に伝える。

### 1-2. 決済代行2ドメインの参照元除外

- 事実: 予約完了の約22%が、決済代行から戻ったときに流入元を失って「参照元」扱いになっている(`api3.veritrans.co.jp` と `fep.sps-system.com`)。
- [ ] 管理 → データストリーム → ウェブのストリーム → タグ設定を行う → 「除外する参照のリストを設定」。
  - 次の2つを「参照ドメインが次を含む」で追加する: `api3.veritrans.co.jp`、`fep.sps-system.com`
- [ ] 設定後に確認: 数日後、`node scripts/analytics/query.mjs` のチャネル別で Referral が減り、予約完了の入口が元の流入元(Organic Search・Direct など)に戻っていく。

### 1-3. ChatGPT を AI チャネルとして扱う

- 事実: `chatgpt.com` の referral 144セッション(28日)が既定チャネルで Referral に入り、AI Assistant に数えられていない。
- [ ] 管理 → データの設定 → チャネルグループ → 「新しいチャネルグループを作成」(既定のグループは編集できないので、コピーして作る)。
  - 「AI Assistant」チャネルの条件に、参照元が `chatgpt.com` に一致するものを足す(`openai.com`・`gemini.google.com`・`perplexity.ai`・`copilot.microsoft.com` も同様に足すかはオーナー判断)。
  - 並び順は Referral より上にする(上のチャネルから先に判定される)。
- [ ] 注意: 新しいチャネルグループは**レポートで選んで使う**必要がある。`query.mjs` は GA4 の既定チャネルグループを読むので、スクリプトの数字は変わらない。スクリプトでも使いたいときは司令塔に相談する。

### 1-4. キーイベントの指定

- [ ] 管理 → イベント → `labola_reserve_complete` と `labola_reserve_complete_program` の「キーイベントとしてマークを付ける」をオンにする(未指定なら)。

## 3. PSI API キー(CrUX の定点取得)

- [ ] Google Cloud コンソール → 「API とサービス」 → ライブラリ → 「PageSpeed Insights API」を有効にする。
- [ ] 「認証情報」 → 「認証情報を作成」 → API キー。キーは「API の制限」で PageSpeed Insights API だけに絞る。
- [ ] `.env.local`(リポジトリ直下・gitignore 済み)に `PSI_API_KEY=<発行したキー>` を1行追記する。**キーの値をチャットやファイルに貼らない。**
- キーが無いときは、`npm run analytics:weekly` は CrUX の節に「PSI_API_KEY が未設定のため…スキップしました」と出して、他の節は普通に動く。
- PSI は1ページあたり数十秒かかる(4ページ × モバイル)。ページ単位の実データが件数不足のページは「オリジンで代替」と出る。
- 注意: PSI の応答キー名は公式ドキュメントで確認できなかったため、最初の実行で指標が「取得不可」になったら司令塔に伝える(実データの応答を見て直す)。

## 5. 週次の読み方(`npm run analytics:weekly`)

出力は画面に出るだけで、個人情報は含まない。どこにも書き込まない。

### GA4 予約完了と予約台帳の週次突合

- `GA4完了` は LaBOLA ホストの `labola_reserve_complete`+`_program` の週次回数(JST・月曜始まり)。`台帳受付` は予約台帳の受付日時が当週のもの(キャンセル済みを含む。テスト予約は除く)。
- 差が **マイナス**(GA4 が少ない): 計測漏れ・別端末で予約した人・LaBOLA 管理画面から入れた予約の疑い。
- 差が **プラス**(GA4 が多い): 完了ページの再読み込み・重複発火の疑い。
- 差が急に変わった週は、GA4 の設定変更(1-1・1-2)や LaBOLA の画面変更を疑う。

### テニスベア行きクリックと申込

- `クリック` は /reserve のイベントカード(`reserve_choice_pickle_event`)の `reservation_click` の週次回数。`申込` はテニスベアのサークルの開催回への申込(参加・キャンセル)を申込日時の週で数えた件数。
- 申込÷クリックは、**同じ人の申込とは限らない**(クリックは1人が何度も押せる、申込は別経路でも入る)。傾向を見るための参考値。
- 対象の開催回数と、申込日時のない申込の数が末尾に出る。

### CrUX

- ページごとに LCP・INP・CLS・FCP・TTFB の p75 と評価(良好/要改善/不良)。目安: LCP 2.5秒以内・INP 200ms 以内・CLS 0.1 以内が「良好」。
- 「オリジンで代替」は、そのページ単体の実データが足りないとき。サイト全体の値を見ている。
