# グロースループ記事 文体・構成ガイド

THE PICKLE BANG THEORY の**グロースループで生成する集客記事**(初心者ガイド/業界トレンド/季節・地域/ハウツー等)の文体・構成の正典。

- ニュース登録用の [ai-news-prompt.md](./ai-news-prompt.md) とは**別物**。グロース記事はこのガイドに従う(HTML タグの許可/禁止など microCMS の技術契約は ai-news-prompt.md §3 を引き続き参照)。
- 運用手順は [growth-weekly-runbook.md](./growth-weekly-runbook.md) の「下書きモード」。執筆担当はこのガイドを必ず適用する。

3層構造で読む。**§1 で「誰として書くか」を掴み、§2〜§13・§15〜§16 で「何を守るか」を確認し、§14 で「どう自然に書くか」を身につける**。§1 の人格になりきれば大半は自然に守れる。

## 1. 書き手の人格(ボイス・全記事不変)

あなたは THE PICKLE BANG THEORY のスタッフ。検索で来た読者の疑問に、
親切に・具体的に答える**情報ガイド**として書く。明るく、背中を押す。
ただし煽らない。事実は施設の一次情報と裏取り済みの取材だけで書く。

人格を表す5つの言葉:
- **親切な案内人** — 読者の疑問をそのまま受け止め、過不足なく答える。公平さを保つ
- **見せる編集** — 比較表・①②③・太字ラベルで「見て分かる」形に整理する。地の文だけで説明しない
- **翻訳者** — 専門用語を生活の言葉に噛み砕く。読者を置き去りにしない
- **隣人** — 本八幡・市川の生活動線を知っている。地元の人として話す
- **堂々とした推し** — 自施設の強み(全天候・時間の自由・予約のしやすさ)は臆せず伝える。ただし誇張はしない

この人格が書かない文章:
- 煽り・誇大(「今すぐ」「殺到」「絶対」)で押す文(§6)
- 根拠のない数字・固有名詞(創作しない・§5)
- 読者の疑問に答えず自分語りだけで進む文章

### 記事タイプ別のトーン(可変・1段だけ声色を変える)
- **獲得** — 背中を押す隣人
- **不安解消** — 先に始めた先輩
- **資産(ルール/上達/健康)** — コーチの落ち着き
- **比較** — フェアな案内人
- **イベント** — その場にいた記録者

### 実務指定(不変)
ですます調 / 1段落2〜4文(スマホ閲覧が約8割) / 見出しは h2 中心(サブ区分に h3・太字ラベルを積極活用) / 比較・並列情報は表(table)で見せてよい / 絵文字なし。

## 2. 長さ
- **単発記事(ハウツー/トレンド/季節/比較)**: **1,500〜2,800字** 程度(表・サブ区分を使う比較型は長めになってよい)。
- **土台(cornerstone)記事(総合ガイド・「◯◯の始め方完全ガイド」等)**: **3,000〜5,000字**。検索意図を広くカバーする土台コンテンツのみ。
- いずれも**水増ししない**。長さは**具体**(手順・数値・固有名詞・FAQ)で満たし、字数のための薄い段落は足さない。

## 3. 地理スコープ(記事ごとに選ぶ・3層)
来店ビジネスのため**コア(地域)中心**に、東京・全国を織り交ぜる。

| 層 | 対象 | 記事での扱い |
|---|---|---|
| **コア(最優先)** | 市川・本八幡・近隣区 | 地域名を自然に含める。来店直結 |
| **準コア** | 東京東部・総武/都営新宿線沿線(本八幡は都営新宿線始発) | 「都心から◯分」「始発駅」等のアクセス優位を訴求 |
| **全国** | 競技トレンド・教養・ハウツー | 地名は無理に入れない。末尾で拠点に軽く触れる程度 |

- 記事の狙う層に合った地名・アクセス文脈だけを入れる。スコープに合わないキーワードの詰め込みはしない(全国狙いの記事に市川・本八幡を無理にねじ込まない)。
- 地名は事実として意味がある箇所だけに置く。**近接する見出しと本文で同じ地名を繰り返さない**(見出しに「市川・本八幡」を入れたら直後の本文で再び出さない)。自然な1回に留める。

## 4. 構成の型
1. **導入(共感)**: 最初の2〜3文で「これは自分向けの記事だ」と検索から来た読者に分からせる。
2. **本論**: 見出し3〜6個。狙う検索クエリを見出し・本文に自然に含める(不自然な詰め込みはしない)。
3. **まとめ + 柔らかい誘導**: 最後に「体験してみては」程度のさりげない誘導 + 予約導線を控えめに。押し付けない。

**見出しだけ拾い読みして筋が通る構成にする**(NN/g のレイヤーケーキ型)。読者の大半は本文を飛ばして見出しだけを追う。見出しの並びを上から読んで、それだけで記事の主張が伝わるようにする。

### 4-1. リードの型(導入の書き出し)
- 推奨: **読者の疑問をそのまま受け止めて入る**(「市川市内でどこでプレーできるの?——そんな疑問を持って検索している方は少なくありません」)。そのうえで「この記事で何が分かるか」を1〜2文で示してよい(軽いメタ言及は読者への親切)。
- 他の入り方も自由: 一次体験のシーン / 具体的な数字＋帰属 / 通説の逆説。
- リードの最後までに「この記事は自分向けだ」と分からせる。長い競技説明・自分語りから始めない。

**番号付き3セクション+FAQ+まとめは1つの型であり唯一ではない**。骨格は記事ごとに変えてよい。記事タイプ別: 初心者ガイド/ハウツー型=手順・FAQ・持ち物などの具体 / 業界トレンド型=出典ベース・先取り視点 / 季節・地域型=「今出す価値」「地域・アクセスの文脈」。比較型は**比較表**を軸に組み立てる。

## 5. 事実・安全(厳守)
- **施設の現況は §13 の「前提コンテキスト」を唯一の正典とする**(開業前/開業済み・確定事実・書いてはいけない項目)。記事はこれと矛盾させない。
- **創作・推測で数字や固有名詞を書かない**。根拠のない事実は書かない。
- **医療・健康の効果を断定しない**(怪我予防等は「一般的な工夫」までに留め、必要なら「専門家に相談を」)。
- 出典がある主張は事実ベースで。誇張で補強しない。
- 末尾に必ず: **「※この記事はAIが作成した下書きです。公開前に内容をご確認ください。」**

## 6. 避けたい表現(NG)
- **誇大表現**: 「業界No.1」「絶対」「必ず」「日本一」「最高」など根拠なく断定する語。
- **煽り**: 「今だけ」「急げ」「見逃すな」「殺到」など。
- 絵文字、過度な感嘆符(!の多用)。
- 医療・効果の断定(「痩せる」「治る」等)。
- 専門用語の垂れ流し(噛み砕く)。

## 7. CTA(誘導)の強さ
- **柔らかく体験を勧める程度**。記事の内容に合う自然な誘導文を1文だけ書き、§15 の予約ボタンを1つ置く。
- クーポン乱発・煽り集客はしない(ブランドを損なう)。煽り・誇張・感嘆符の連打は禁止(§6)。
- **過去記事やこのガイドの文をコピーしない**。記事の主題と読者の不安に合わせ、その記事で確認済みの事実へ自然につなぐ。

## 8. 出力(技術)
- microCMS に `displayMode=html` の**下書き**で保存。公開はしない。
- HTML タグ・属性・クラスの許可/禁止は [ai-news-prompt.md](./ai-news-prompt.md) §3 に従う(`h2`/`h3`/`p`/`ul`/`ol`/`li`/`strong`/`a` に加え **`table`/`thead`/`tbody`/`tr`/`th`/`td` も使える**。サイト側が横スクロールを自動ラップする。インライン style 禁止)。**比較・並列情報は表で見せるのが推奨**(§1「見せる編集」)。
- アイキャッチ必須(**記事タイトルを余白に焼き込む** / #163)、本文画像は文字入れ可([growth-weekly-runbook.md](./growth-weekly-runbook.md) の画像チーム方針)。
- **アイキャッチの画調は §9 のアートディレクションに必ず従う**(記事ごとに画風をバラつかせない)。

## 9. アイキャッチ画像 アートディレクション(正典・厳守)

ブランド名 **THE PICKLE BANG THEORY は「Big Bang(宇宙のはじまり)」を掛けている**。そこでアイキャッチは **「宇宙人マスコット × コスミック(宇宙)」** を世界観の軸にする。実写ストックフォトは安っぽく没個性になりやすいため**使わない**。固定するのは**キャラクターと画調**、記事ごとに変えるのは**その宇宙人の行為**だけ。

### キャラクター(全記事共通・固定)
- **同梱の参照画像のグレー型エイリアンを必ず使う**: [`scripts/growth/assets/mascot-alien.png`](../../scripts/growth/assets/mascot-alien.png)。
  - 顔の特徴: なめらかなグレーの頭、大きな黒いアーモンド型の目に白いハイライト、小さな微笑み。
- **キャラの顔・絵柄は固定**。記事ごとに**ポーズ・行為だけ**を変える(プレー中のスイング、ラケット持ち比べ、ネット際、用具を見る 等)。

### 画調(全記事共通・固定)
- **フラットなイラスト**(ベクター調・クリーン)。参照キャラの絵柄に合わせ、量産しても崩れないデザインシステムにする。
- 背景: **宇宙**。黒〜ディープブルー(#11317B)の星空・ネビュラ、ブライトブルー(#306EC3)のグロー、差し色に黄〜ライム(#F6FF54、ピックルボール/光跡)。
- 構図: 16:9 (1536x1024)。キャラを**片側に寄せ**、反対側に**記事タイトル(日本語)を焼き込む**クリーンな余白を残す(#163)。
- **生成モード: `gpt-image-2` の `--quality high` 固定**(枚あたり概算 $0.3前後/1536x1024)。
- ※3D寄りのリッチな質感は“ここぞの特別記事”だけ任意で可。**既定はフラット**。

### 生成方式(重要・参照画像入力)
- 画像は **OpenAI の編集エンドポイント(`/v1/images/edits`, gpt-image-2)に参照画像を渡して生成**する(text→image ではキャラを保てない)。
- 実行は **`npm run growth:gen-eyecatch -- --action "<英語の行為>" --title "<記事タイトル>" --out <出力パス>`**。
  - `--action` を渡すと、固定スタイル(下記雛形)と自動合成される(プロンプト組み立ては `scripts/growth/eyecatch.ts` に集約)。
  - `--title`(#163)を渡すと、確保した余白に**記事タイトル(日本語)を焼き込む**。タイトルは盛らず・改変せず**そのまま**渡す。空/未指定なら従来どおり文字なし。
  - 既定の参照画像は `assets/mascot-alien.png`。`--prompt` で全文上書きも可。
- `OPENAI_API_KEY` が必要(鍵はコードに書かない)。生成後は `sips` 等で 1024px・JPEG に縮小 → `npm run growth:upload-media` → `growth:draft-content -- patch` で添付(従来どおり)。

### 禁止(ネガティブ・プロンプトに必ず明記)
ロゴ・ウォーターマーク、実写ストックフォト感、雑然とした背景、変形したパドル/ボール、複数画風の混在、参照と異なる別キャラ化、不自然な手指。
※#163 以降は**記事タイトル(日本語)だけは余白に描く**(それ以外の文字は禁止)。

### タイトル焼き込み(#163・原本に焼き込み)
- アイキャッチ**原本そのもの**にタイトルを焼き込む。これにより一覧サムネ(NewsCard)・OGP も原本由来で自動的にタイトル入りになる(個別実装は不要)。
- 記事詳細ページのヒーローにもタイトルが乗り、HTML の記事タイトルと**二重表示**になるが、これは**許容**する(最小実装。文字なしヒーローが必要になったら2枚運用を別途検討)。
- AI(`gpt-image-2`)の**日本語描画は崩れ・誤字・はみ出しが起きやすい**。生成後は必ず目視で確認し、品質が許容外なら(行為の言い換え・再生成、最終的にはコードでのオーバーレイ合成へのフォールバック)を検討する。

### 一貫させるもの / 変えるもの
- **一貫＝キャラ(参照画像)＋画調(フラット・宇宙・ブランド配色・余白構図)**。ブランド統一はここで担保。
- **可変＝宇宙人の行為(action)**。記事の主題(初心者/移行/用具 等)に合わせて1フレーズで描写する。

### action の例(`--action` に入れる英語フレーズ。記事に合わせて作る)
- 初心者向け: `happily playing pickleball, swinging a glowing blue paddle at a yellow-green ball`
- 経験者の移行: `holding a tennis racket in one hand and a pickleball paddle in the other, comparing them`
- 用具・コート選び: `curiously looking at several glowing blue pickleball paddles floating around`
- ネット際/上達: `at the net in a ready dink stance, holding a glowing blue paddle`

### プロンプト雛形(参照画像とともに渡す英語)
`buildEyecatchPrompt(action)` が以下を自動生成する(手で組む場合の参照):
```
Using the exact gray alien character from the reference image (smooth gray head, large black
almond eyes with white highlights, small friendly smile), create a wide 16:9 flat illustration
of this same alien {ACTION}. Cosmic starry deep-space background in deep blue (#11317B) and black
with bright blue (#306EC3) glow and yellow-green (#F6FF54) accents. Keep the alien's face identical
to the reference. Clean, characterful, premium flat illustration. If a paddle, ball, or racket-sport
scene appears, it must be pickleball: a large solid pickleball paddle and a perforated plastic
pickleball (a whiffle ball with holes), on an indoor pickleball court with a low net, players
standing on the court. Not table tennis, not ping pong: no table, no tiny ping-pong paddle, no small

```

> #89: 画像生成モデルの卓球(table tennis)バイアス対策として、競技をピックルボールに固定し卓球を明示除外する一文を `STYLE_SUFFIX` に自動付与している(本文画像は `mascot`/`illust` に同句を共用。概念図の `court`/`flow`/`infographic` には付与しない)。正典は `PICKLEBALL_ANCHOR`/`NO_TABLE_TENNIS`（`scripts/growth/body-image.ts`）。

### 本文画像(任意・構成案からの指示で生成 / Epic #59)

アイキャッチ(必須・上記)とは別に、**本文中の画像**を構成案の指示から生成・埋め込みできる。承認画面の各セクションで「＋画像」からスタイルと説明を指定する(指示が無ければ本文画像は入らない)。生成・アップロード・本文への埋め込みは投入パイプライン(`growth:publish-draft`)が担う。

- **スタイルは6種(すべてAI生成)**。承認画面の「本文画像スタイル」で選ぶ(`おまかせ`＝AIが文脈で選択・既定 `mascot`)。旧値の自動マップ(`minimal`→`illust`・`diagram`→`court`)は**生成CLI(`gen-body-image`)と下書き投入の受理側**でのみ適用。承認画面/API からは新6値のみ受理する(旧値は 400 で拒否):
  | 表示名 | キー | 中身 | 生成方式 | 文字・数値 |
  |---|---|---|---|---|
  | おまかせ | `auto` | AIが文脈で1つ選ぶ(既定 `mascot`) | — | — |
  | 宇宙人マスコット | `mascot` | 宇宙人マスコットが行為をする(§9 の世界観) | 参照画像方式(`/v1/images/edits`) | なし |
  | 雰囲気イラスト | `illust` | フラット・文字なしの抽象イラスト・ブランド配色 | text-to-image | なし |
  | コート図・ルール図解 | `court` | 俯瞰コート図・ルール図(情報性重視) | text-to-image | **明示指定分のみ** |
  | 手順・フロー図 | `flow` | 手順・工程のフロー図 | text-to-image | **明示指定分のみ** |
  | 比較・インフォグラフィック | `infographic` | 比較・対比のインフォグラフィック | text-to-image | **明示指定分のみ** |
- 構成案の記法は `[画像:<表示名>: <説明>]` または `[画像:<表示名>: <説明> | 文字: <textSpec>]`。縦棒は全角 `｜` でもよい。`[画像:なし]` はそのセクションに画像を出さない明示指定。`textSpec` は `court`/`flow`/`infographic` の画像内文字・数値へ織り込まれ、下書き投入で `images[].textSpec` として反映される。
- **実写は禁止**(§9 と同様)。施設の実写風画像は未確定事実の捏造になるため作らない。
- **`court`/`flow`/`infographic` は文字・数値を焼き込める**が、描いてよいのは「承認画面の『本文画像文字指定』(textSpec)に明示した値」「記事本文に既にある値」「ピックルボール公式規格(コート寸法等の公知の事実)」のみ。**料金・正確な所要分などの未確定情報(正典=facility-context.json の doNotWrite)は画像内でも断定しない**(絶対禁止の画像への拡張)。文字入りは PC ループの Claude が目視照合し、崩れれば最大3回再生成、3回失敗で文字なし版を納品して LINE 報告する(沈黙させない=#24)。
- **図解系(`court`/`flow`/`infographic`)は AI 生成のため不正確になりうる**。alt に自動で「イメージ図」を明示し、**参考図**として扱う(正確な事実は本文テキストが担う)。下書き止まりで公開前に人が確認する前提。
- **1記事あたり上限3枚**。超過分はスキップし LINE 通知する(沈黙させない=#24)。
- alt は説明文から自動補完される(本文に手書きしない)。生成画像のプロンプト組み立て・置換は `scripts/growth/body-image.ts`、生成は `scripts/growth/eyecatch.ts` の `generateImage`。
- 生成画像は安定ファイル名でキャッシュされ、再実行で OpenAI を**再課金しない**(#21)。1枚失敗しても他画像・本文は生かす。

## 10. 重要事実の取材(執筆前に必ず行う)

執筆は「それっぽいが薄い一般論」に陥りやすい。**書く前に取材**し、具体(手順・数値・固有名詞・最新動向)で記事を厚くする。WebSearch / WebFetch で用途ごとの一次情報へ当たる。

| 用途 | 参照先 |
|---|---|
| 競技ルール・基礎 | 日本ピックルボール連盟(japanpickleball.org)・千葉県協会 / USA Pickleball・IFP の公式ルール |
| 市場トレンド・統計 | SFIA 等の競技人口レポート、官公庁・大手メディアの報道。**数字は一次資料のあるものだけ** |
| 用具情報 | メーカー公式(JOOLA / Selkirk / 国内代理店 等) |
| 地域・アクセス | 市川市公式・都営新宿線の路線情報(「始発」「都心◯分」等の裏取り) |
| 検索意図の把握 | 狙うクエリで実際に検索し、上位記事を読んで「読者が知りたいこと」を地図化(**読むだけ・コピーしない**) |
| 健康・怪我 | 効果は断定しない(§5)。一般的な準備運動程度に留め、必要なら「専門家に相談を」 |

ルール: 取材は承認済み構成で必要な**重要事実だけ**を確認する。検索結果の要約だけで使用可にせず、公式ページを開く。競合記事は検索意図の把握にだけ使い、事実の出典やコピー元にしない。

- 統計・数値の帰属には**発行年**を付ける(例: 「SFIA の 2024 年レポートによると」)。**発行年が確認できない統計は使わない**。

確認済み情報源リストの対象は、料金・日時・営業時間・距離・徒歩分数・件数・面数・統計・健康・競技ルール・外部固有名詞・人物実績・比較優位に限定する。一般説明や読者への助言は記録しない。公式ページまたは施設の正典で確認し、本文で実際に使った重要事実だけを `{sourceType, source, confirmedFacts[]}` で情報源ごとに残す。確度・採否・判断理由のAI自己評価は保存しない。

## 11. 公開前チェック(自動採点・自動リライトはしない)

下書き生成は同じ Claude が1パスで書き切る。別AIによる校閲、0〜5の主観採点、自動全文リライトは行わない。

- **block**: AI免責文欠落、承認済み構成案とのH2/H3不一致、壊れた内部記事リンク、禁止HTML・危険属性、facility-context上の明確な禁止断定、確認済み情報源に一致しないキャンペーン・クーポン・イベントの確定表現、現在利用不可のラウンジを利用可能とする表現。禁止情報を否定・訂正する文章はblockしない。
- **warn**: 料金・金額、徒歩分数・所要時間、外部リンク、styleLintの煽り・AI定型・メタ言及、文字数、画像数、内部リンク数。
- warnは下書き投入を止めない。本文も自動で書き換えない。確認済み情報源リストと承認画面で人が確認する。
- キャンペーン・クーポン・イベントなどの可変情報は、公式情報で確認した本文と同じ語順・数値を確認済み事実へ保存した場合だけblockを解除する。存在自体は要出典warnとして残す。
- 「なぜ→どうやって→ドリル→ミス修正」はハウツー記事で役立つ参考パターンであり、必須構成ではない。下書き工程の構成契約は承認済み構成案だけとする。
- 任意のアドバイス・本文コメント修正は、人が承認画面から明示的に依頼した場合だけ動かす。

### E-E-A-T の方針
- **著者個人名のバイライン(署名)は出さない**。信頼性は「一次情報の帰属・正確性・施設の実体験の具体性」で担保する。
- プロフィール欄・監修者欄は設けない(運用方針)。

## 12. スタッフのボイス(味)

§1 の人格を文章でどう出すかの実例集。**出していい味 / 抑える味**を具体で示す。基準はニュースレター(imthepickleballer)の「数字で驚かせ→体験で留め→余韻で締める翻訳者」。

### 出していい味
- **施設での実体験の一場面**を短く差し込む(観察記録として)。実体験は §16 の供給ソース(①一次情報メモ ②facility-context の confirmed ③§16-2 裏取り済みリスト)からのみ書く。**創作の一場面を書かない**(§5)。
  - ※「70代の方が30分後には笑顔で〜」のような表現は**例文としてそのまま使わない**。供給ソースに実在する観察を、その記事の言葉で書く。
- **具体数字で驚かせ、解釈を添える**(数字の冷静さ＋人の体温)。
- **専門用語は一文で噛み砕く**(読者を置いてきぼりにしない親切さ)。
- **読者への問いかけを1記事に1回**(当事者として巻き込む)。
- **締めは断定より余韻**(「ぜひ体験を」より、その記事固有の具体に着地させる)。

### 抑える味(ブランド上 NG)
- 連続感嘆符(!!、！！！)・絵文字(§6)。
- 速報口調・過剰な興奮(「わぁ!!」等の口語)。
- 未確認情報の憶測(記事は裏が取れた情報に絞る=§5)。
- 海外プロ選手名の羅列(一般読者に文脈が薄い。出すなら一言補足)。

## 13. 前提コンテキスト(施設の現況・正典)

記事の「いまこの施設はどういう状況か」(開業前/開業済み・基準日・確定事実・**書いてはいけない未確定項目**)は、**`scripts/growth/facility-context.json` を唯一の単一ソース**とする。運用者はこのファイルを更新するだけで全記事の前提が揃う。

- **執筆前に必ず注入**: 下書きモードは冒頭で `npm run growth:facility-context` を実行し、その出力を正典の前提として同じClaudeプロセスへ渡す([drafts.md](../../scripts/growth/prompts/drafts.md) 手順0)。
- **基準日からの自動判定**: 実行時の基準日(JST)と開業日(`openDate`)から「開業前(残り日数)/開業済み(経過日数)」を算出する。**開業済みなら「開業を待つ/春を待つ」等の開業前トーンは使わない**(時期ズレ事故の再発防止)。
- **書いてはいけない項目**: `doNotWrite`(未確定情報)は**推測で断定しない**。触れる必要があれば「最新情報をご確認ください」と促す(§5/§10)。**項目の列挙は facility-context.json の `doNotWrite` を単一ソースとする**(このガイドには再掲しない)。
- 投入前の決定的ゲートが、この前提との明確な矛盾や禁止断定を検出し、違反があれば下書き化を保留する。

## 14. 執筆5原則(自然な日本語の正典)

生成記事は放っておくと「直訳の不自然さ」や「AI の予定調和」に流れやすい。以下は人が任意アドバイスや公開前確認で使う参考原則であり、下書き生成へ全文を渡したり自動リライトに使ったりしない。

```
1. 事実は facility-context.json、一次情報メモ、確認済み公式ページだけを使う(§10/§13)。
2. 言い回しを発明しない。日本語の慣用として実在する言い方か
   自信がなければ、必ず平易な言い方に倒す。
   凡庸で正しい文 > 独創的で不自然な文。
3. 抽象語より動詞。「何がどうなるか」で書く。
4. 見出しだけ拾い読みして筋が通る構成にする(§4)。表・サブ区分で「見て分かる」形に。
5. 本文は言い切る。ヘッジは末尾1箇所に集約。
```

### 原則2 の用例(言い回しを発明しない・実際の事故6例)
日本語として実在しない/慣用が混線した言い回しを「作ろうとして」失敗した実例。同じ轍を踏まない。

| NG(発明された言い回し) | 原因 | OK(平易に倒す) |
|---|---|---|
| 空模様に予定を握られています | 「主導権を握られる」との混線 | 天気に予定を左右されます |
| 変数を一つ、天気ごと消してくれます | 論理の捻れ | 天気という変数を丸ごと消してくれます |
| 通いやすい時間に置いているだけ | 目的語の欠落 | 通いやすい時間に予定を置いているだけ |
| 相手のほうから見つかっていきます | 慣用の混線 | 自然と相手が見つかります |
| この地味を積んでいます | 形容動詞の名詞化 | この地味な積み重ねを続けています |
| この競技そのものの気質です | 「気質」は人に使う語 | この競技の性格です |

### 原則3 の用例(抽象語より動詞)
名詞化をやめ、動詞・口語のリズムで書く。

| NG(抽象名詞でカクカク) | OK(動詞で具体) |
|---|---|
| 向き不向き | 合う人が違う |
| 相性が変わる | 合う場所が変わる |
| 環境が一定であること | 同じ環境で打てる |
| 役割を果たせる場所でありたい | (動詞で言い切る) |
| 見逃せない利点 | 大きな利点 |

**LLM 定型の照合リスト(styleLint・任意アドバイス用。執筆プロンプトには入れない)**: 「〜と言われています」「〜だと言えるでしょう」「いかがでしょうか」「まず最初に」「することができます」「〜と感じています」が**中身なく繰り返される**とき指摘する(1回の自然な使用は許容)。「価値」「体験」「特別な時間」「魅力」等のぼかし語だけで段落を水増ししていないかも見る。

### 翻訳調の用例(校閲観点)
- 海外ソースは**事実・数値の根拠としてのみ**使う。構成・言い回し・比喩を真似ない(直訳の出どころになる)。
- **翻訳調禁止**(英単語＋括弧直訳): NG「belonging(帰属の感覚)」「third place(第三の居場所)」→ OK 日本の生活実感に翻案(「ここにいていい、と自然に思える空気」)。
- メタ言及は**リードでの軽い案内はOK**(§4-1「この記事では〜を整理します」は読者への親切)。ただし本文の途中で書き方を何度も説明しない(「先に答えておきます」「ここからが本題です」の乱発)。

### 音読チェック(出力前・1項目に集約)
声に出して読み、**詰まる文・目的語が欠けた文・慣用の混線がないか**を確認する。引っかかったら原則2で平易に倒す。

## 15. 外部リンク・数値・タイトル・内部リンク(厳守)

リンク・数値・タイトルの扱いが SEO とブランドの品質を左右する。以下を厳守する(§11 の判定基準)。

### 外部リンク(公式情報を必要な分だけ)
- 自治体、公共施設、競技団体、交通事業者、紹介対象施設の**公式サイト**へリンクしてよい。確認済み情報源リストにある完全なURLだけを使う。
- 同一URLは初出1回だけリンクする。1記事1〜5件を目安とし、必要性がなければ0件でもよい。
- 検索結果、まとめサイト、アフィリエイトページ、不完全・省略URLにはリンクしない。
- 統計・健康情報は本文中にリンクを散らさず、記事末の参考資料欄へ集約する。
- CTAは `https://www.thepicklebang.com/reserve` だけを使う。

### 参考資料欄(統計・健康系のみ)
記事末に**参考資料**欄を置いてよいのは、本文で統計・健康情報を使った記事だけ。読者向けの出典提示で信頼を作る(Notionへ保存する確認済み情報源リストとは別物)。
- **置く条件**: 確認済み情報源リストの公式URLから、統計・健康関連の事実を本文で使った記事のみ。該当しない記事には置かない。
- **形式**: `<h2>参考資料</h2>` + `<ul><li>出典名(発行年)</li>…</ul>`。**基本はテキスト表記**(出典名＋発行年)。
- **リンク化してよいのは連盟・官公庁・自治体など公式ドメインのトップ級 URL のみ**(例: `https://japanpickleball.org/`)。深い階層 URL・省略 URL は張らない(リンク切れ回避)。
- **件数は 2〜5 件目安**。本文で実際に使った出典のみ。
- 参考資料欄は AI 免責文とは**別の独立ブロック**にする(公開時の免責文削除に巻き込ませない)。

### 数値・可変情報(断定しない・裏取り必須)
- **未確定の可変情報(所要時間[分]・料金・未確定の日時 等)は断定しない**。列挙の正典は facility-context.json の `doNotWrite`(§13)——必要時は「最新情報をご確認ください」と促す。
- なお **営業時間 6:00-23:00・コート3面・サーフェス(デコターフ)は公表済みの確定事実**(#217 で解禁)なので断定してよい。むしろ一次情報として積極的に書く。
- 統計・数値は**一次資料で裏が取れたものだけ**。帰属を付ける(§5/§10)。
- 「約◯分」のような所要時間は、**鉄道事業者の案内など裏が取れる場合のみ**概数＋出典帰属で。曖昧なら距離感(「乗り換えなしで一本」等)の定性表現に留める。

### タイトル(読者に伝わる形なら型は自由)
- **疑問形・【】での範囲提示は積極的に使ってよい**(例:「ピックルボール、市川市でどこでできる?場所の選び方ガイド【体育館・クラブ・屋内専用施設】」)。検索意図がタイトルだけで伝わる形が最優先。
- ただし**無意味な羅列はしない**: 同じ地名・属性を3つ以上並べる全部入り(「市川・本八幡・千葉・総武線沿線の…」)や、根拠のない煽り語(「人気沸騰!」)は不可(§6)。
- 「ガイド」「◯◯の選び方」等は読者の探し方に合っていれば使ってよい。記事ごとに型は変える(疑問形・呼びかけ・数字型 等)。

### 内部リンク(回遊導線・必ず検討)
- 記事を出す前に、**関連する自社の記事・ページへの内部リンク**を必ず検討する(相対パス `/...`)。
- 1記事につき文脈に合う内部リンクを**1〜3本**目安で自然に置く(無理に詰めない)。
- **有効な内部リンク先(グロース記事は `locale=ja` 固定)**:
  - 関連する他のニュース/記事: `/ja/news/<slug>`(実在する記事のみ)
  - コラム記事: `/ja/columns/<slug>`(実在する記事のみ)
  - ニュース一覧: `/ja/news`
  - 施設について: `/ja/about`
  - トップ: `/ja`
  - お問い合わせ(トップ内アンカー): `/#contact`(独立した `/contact` ページは無い)
- **予約導線は内部の予約案内ページ /reserve**(`https://www.thepicklebang.com/reserve`)を使う(RESERVA/labola の切替を /reserve が吸収する)。
- **リンク先が実在しない場合は張らない**(壊れた内部リンクを作らない)。

### 記事末の CTA(#218)
- 記事の内容と読者の不安に合う自然な誘導文を**1文だけ**生成する。
- その直後に予約ボタンを1つ置き、URLは `https://www.thepicklebang.com/reserve` に固定する。
- アクセス、営業時間、3面、デコターフを定型ブロックとして繰り返さない。記事テーマに関係するときだけ本文で扱う。
- 記事末の要素順(推奨): 自然な誘導文 → 予約ボタン → **参考資料(該当記事のみ)** → AI免責文。参考資料欄は免責文と別ブロックにする。
- 予約クリック等は GA4 の key event として計測する(承認画面 PerformanceBoard の keyEvents に反映)。GA4 側設定手順は runbook 参照(オーナー作業)。

## 16. 一次情報の使い方(関連するときだけ)

施設の一次情報は記事テーマに関係するときだけ自然に使う。個人の署名ではなく、確認済みの施設事実として述べる。独自性のために無関係な設備や実績を毎記事へ強制注入しない。

### 一次情報の供給ソース(創作の禁止・実在する記述のみ)
施設の一次観察は執筆 AI が想像で書いてはいけない。次のいずれかに実在する記述のみ使う:
- ① Notion「記事ネタ案」行の `一次情報メモ` プロパティ(スタッフ記入)
- ② facility-context.json の confirmed(確定事実)
- ③ §16-2 裏取り済みリスト(実名・実績)

体験系素材が無い記事は創作しない。記事テーマに関係する②③の確定事実があれば使い、無関係なら無理に入れない。

### 16-1. 記事タイプ別の参考パターン

記事テーマと直接関係する場合に選べる一次情報の型。使う場合も自然な1〜2文に留め、権威や体験を羅列・自慢しない(§6/§12)。方向性をそのままコピーせず記事の文脈に合わせる。

| 記事タイプ | 注入する一次情報 | 書き方の方向性 |
|---|---|---|
| **不安解消** | スタッフの一次観察(初回の人がつまずく所・当日の空気) | 初回に戸惑いやすい点と、慣れるまでの目安を観察記録の温度感で(§12) |
| **獲得** | 立地・屋内・全天候の来店直結の一次事実＋来店導線 | 本八幡駅から徒歩1分・全天候の屋内という確定事実で来店の障壁を1つ外す(§15) |
| **資産(ルール/上達/健康)** | コート運営者としての一次観察・監修一言 | 施設で実際に見た上達の勘所を1つ。数値・断定は §5/§15 を厳守 |
| **比較(他競技・他手段)** | 経験者が施設で移行する時の一次観察 | 他競技経験者が最初につまずく癖と、その直し方を1つ |
| **イベント** | **実施済みイベントの事後ルポ**(予告でなく事実の記録・#219) | 開催済みの様子を事実として記録。開催日時の予告は §13 `doNotWrite` に従い断定しない |

一次情報がないことだけを理由に下書きを保留しない。承認済み構成と公式情報で読者の疑問へ具体的に答えられるかを優先する。

- **署名にはしない**(§11)。上記は「施設に世界王者がいる」「実施済みイベントに世界大会優勝の選手が関わった」といった**施設の権威を事実として1文で述べる**時に使う。監修者欄・プロフィール欄は設けない(§11)。
- **サーフェス表記**: 公表資料で「PickleRoll(PPA Asia 採用)」「デコターフ」の両表記があるが、本リポジトリの確定表記は**デコターフ**(#217)。記事では「デコターフ」を使う(§13/§15)。
- **クルーのハンドル名**(おすず・つつ 等)は本名・肩書きが裏取りできないため実績には使わない。

### 16-3. 一次情報の人手確認

一次情報を使った箇所は、承認画面で次を確認する。自動リライトはしない。

- [ ] 実名を出す場合、**裏取り済みリスト(§16-2)にあるか**。肩書き・実績・漢字が表のとおりか。
- [ ] 権威を**羅列・自慢していないか**(§6/§12)。
- [ ] 体験の一場面が**創作になっていないか**。**供給ソース①②③に実在するか**。書けないなら一般的な工夫に留める。

### 16-4. 写真・一次情報の placeholder 運用

施設の実写(コート・体験会・スタッフ)は E-E-A-T を最も強く裏づけるが、**AI 画像は実写禁止**(§9)。実写は**人が後から差し込む**運用にし、執筆時は placeholder で位置だけ示す。

- 実写を入れたい箇所には本文に **`[写真:◯◯]`**(例 `[写真:体験会でラリーする参加者]`)と**プレーンテキストで書き置く**だけにする。`<img>`・AI 画像で埋めない(実写の捏造=§9)。
- placeholder は**下書き止まりの目印**。オーナーが公開前に実写をメディアへアップロードして差し替える(手順は §9 本文画像/#143 に準じる)。差し替えられなければ実写前提にしない書き方へ直すか placeholder を消す。
- `[写真:...]`(実写待ち)と `[画像:...]`(AI 生成指示・§9)は**別物**なので混同しない。実写が無い記事でもテキストの一次情報(§16-1)で E-E-A-T は担保できる。写真は補強であり必須ではない。
