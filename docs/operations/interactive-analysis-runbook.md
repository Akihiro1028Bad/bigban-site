# 対話型分析セッション運用ガイド(週次)

> 分析の正本は「毎週の対話セッション + 最小スクリプト」。旧・計測ループ(#C4)・週次モード・review-due の代替。
> 背景と移行判断: `docs/reviews/2026-08-04-growth-and-site-review.md`

## データソース

| ソース | 取得方法 | 備考 |
|---|---|---|
| GA4 / Search Console | `node scripts/analytics/query.mjs`(`.env.local` の OAuth) | 読み取り専用 |
| Labola 予約台帳・会員台帳 | Notion MCP の SQL 集計 | **集計値のみ。個票(氏名・連絡先等)は出力しない** |
| microCMS | microCMS MCP | 記事の公開状況 |
| LINE 友だち数 | query.mjs に同居(通知用トークン流用) | ベストエフォート |
| freee | freee MCP(要認可) | 認可後、月初アジェンダに売上を追加 |
| IG フォロワー・Google 口コミ | オーナーが口頭で共有 | 自動化しない(月1・1分) |

## 週次セッション(毎週木曜・15〜20分)

Claude Code をこのリポジトリで開き、「週次分析やろう」と言うだけ。手順:

```
【毎週やる】
① 予約ペース : 今週の新規予約・キャンセル・来週の埋まり(台帳)
② 稼働の谷   : 直近7日+今後7日の曜日×時間帯で空きが目立つ枠(主KPI=稼働率)
③ 流入速報   : query.mjs(既定7日)の前週比。急変だけ拾う
④ 一次情報   : オーナーから→現場の肌感・イベント予定・打ち手・システム変更
→ 出力: 今週のアクション1〜2個(なければ「なし」でよい)

【月初の週だけ追加(+15分)】
⑤ 月次確定   : 前月の稼働率・リピート率・ビジター→会員転換・PBT Club推移
⑥ SEO        : query.mjs --days 28 の取りこぼしクエリ→記事ネタ判定
⑦ 記事成績   : 公開記事別の表示・順位→継続/改稿判定(旧 review-due の代替)
              + IG フォロワー・口コミ現状値の共有
```

### コマンド

```bash
node scripts/analytics/query.mjs            # 週次(直近7日 vs 前7日)
node scripts/analytics/query.mjs --days 28  # 月初(28日窓 + SEO詳細)
```

## 集計ルール

- **台帳の PII**: 分析は SQL 集計値のみ。氏名・住所・電話・生年月日・メールを会話・成果物に書き出さない。年齢層・性別は集計単位でのみ可。
- **時間帯の表記ゆれ**: 台帳の `時間帯` は `10:00～12:00` / `10:00-12:00` / `10:00〜12:00` が混在。集計時は開始時刻(先頭5文字)で正規化する。
- **ベースライン**: 予約システム移行(2026-08-03 完了)前の台帳は不完全。**需要トレンドは 2026年8月以降のデータだけで判断**し、7月以前との比較を根拠にしない。
- **稼働率の概算**: 有効予約件数 × 平均2h ÷ (3面 × 17h × 日数)。練習会・イベント枠は含まれない粗い推定として扱う。
- **指名クエリ**: 「ピックルバン」「pickle bang」「PBT」「セオリー」系は指名。SEO の伸びしろ判断は非指名クエリで行う。

## 判断の型

- ③で前週比 ±30% を超える変動があれば、原因(記事公開・SNS・システム変更・季節)を④の一次情報と突き合わせてから解釈する。数字だけで断定しない。
- ⑦の改稿判定: 表示があるのに CTR が低い→タイトル改稿を検討 / 表示自体がない→内部リンク・新記事を検討。
- アクションは毎週最大2個。積み残しは翌週に持ち越さず、月初⑤で棚卸しする。
