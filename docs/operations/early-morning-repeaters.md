# 早朝ピックル 常連一覧の使い方(スタッフ向け)

Notion「早朝ピックル常連」に、早朝ピックルの参加者が1人1行で並んでいます。1日2回(朝8:30・夜20:30)自動で更新されます。前夜21時には、翌朝の参加者一覧が LINE グループに届きます。

## スタッフが書く欄(自動更新で消えません)

- **リワード済み**(早朝常連): 特典を渡した節目(5・10・20…)を選ぶ。「未渡し節目」から消える
- **メモ**(早朝常連): 自由記述
- **出欠**(早朝参加記録): 申込したのに来なかった回に「欠席」を付ける。その回は回数から外れる(任意)

## 同じ人が2行に分かれているとき

テニスベアと LaBOLA の両方で申し込む人は、最初は別々の行になります。テニスベア側の行(テニスベアIDがある行)の「LaBOLA氏名」に、LaBOLA の予約名をそのまま入れてください。次の自動更新で1行にまとまります(リワード済みは両方に付いていた節目がすべて残ります（重複なし）、メモは空の方に移ります)。未対応の人はビュー「LaBOLA氏名が未対応」に出ます。

## 数え方

- テニスベアのゲスト枠(「LBゲスト1」など)は数えません。LaBOLA 予約から直接数えるため、ゲスト枠の入力漏れがあっても回数は正しくなります
- 同じ日に両方で申し込んでいても1回です
- 「参加」は申込ベースです。来なかった回は「出欠」で外してください
- 早朝は火曜=初中級、木曜=中級以上の2クラスです。Notion の常連一覧には全体の「累計」(リワードの基準)のほかに、「初中級(火)」「中級以上(木)」の参加回数の列があります
- 「状態」はクラスごとに判定します。参加しているクラスのすべてがご無沙汰なら「ご無沙汰」、いずれかで常連なら「常連」です。木曜の休止のようにクラスの開催がなかった期間は数えないので、休止中のクラスがあっても、その理由でご無沙汰にはなりません

## 主催者・スタッフの除外

- イベントの主催者は参加者一覧に自動で入るため、一覧・回数から自動で除外されます
- ほかにも除外したいスタッフがいるときは、テニスベアの数値 ID を `scripts/early-morning/config.ts` の `EXCLUDED_TB_USER_IDS` に加えます(オーナーに依頼してください。名前は書きません)

## LINE の前夜通知の見方

- 見出しにクラスが出ます(例: 「10/6(火) 6:00 初中級」)
- 各参加者の行に、全体の「N回目」が出ます(初めての方は「N回目」ではなく「初参加 🔰」)
- その下に、灰色の小さい文字で所見が1行出ます。クラスごとに数えた文言で、火曜は初中級、木曜は中級以上の実績から作ります。例:
  - 「火曜 皆勤（8/4から8回連続）」
  - 「木曜 11回中6回・前回 8/20」
  - 「初めての方。声かけをお願いします」
  - 「2回目（前回 9/29 が初参加）」
- 所見は自動で決まる定型文です(AI は使っていません)。翌日の回そのものは含めず、それ以前の実績だけで作ります

## 止め方

- 通知だけ止める: claude.ai のルーチン一覧で「早朝前夜通知」を無効にする(集計は続く)
- 集計も止める: Claude デスクトップの定期タスク `early-morning-sync` を無効にする
- Notion のデータはそのまま残る。再開すれば全期間を数え直すので、止めていた間の分も自動で埋まる

## 困ったとき

- LINE に「⚠ 最新ではありません」と出る: Mac が起動していなかったため、前回の集計を送っています
- LINE に「⚠ …の取得に失敗」と出る: テニスベア・予約台帳・Notion のどれかが読み書きできませんでした。翌日も続く場合はオーナーへ
- LINE に「⚠ テニスベアの処理に失敗」が続き、Notion の「次回の早朝(通知橋渡し)」に「テニスベアの開催回が前回より欠けています」とある: テニスベアで過去の早朝イベントが削除・時間変更されたため、安全のため集計を止めています。該当日の「早朝開催回」の行をアーカイブすると再開します(わからなければオーナーへ)
