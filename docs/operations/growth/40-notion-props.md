# Notion「記事ネタ案」DB 必要プロパティ一覧

> 各ループは pull 型で Notion にプロパティを読み書きする。**事前追加が前提**だが、コードは**欠落耐性**(未追加でも沈黙落ちせず動く/報告する)。
> data source 例: `5adab8b1-f182-4123-b963-9463a2580d4a`。詳細仕様は各ループの節([30-loops.md](30-loops.md) 等)。

## ステータス・基本

| プロパティ | 型 | 用途 |
|---|---|---|
| `ステータス` | select | `承認`/`生成中`(#108)/`下書き作成済み`/`却下`/`公開済み`。**「生成中」値の事前追加が前提**。 |
| `タイトル案` | title | 下書きタイトルにそのまま使う(#176)。修正ループ(#139B)で上書き可。 |

## 仮説プロパティ(週次 #計測強化 S5・下書きブリーフで再利用)

`狙う読者` / `検索意図` / `想定CTA` / `成功指標` / `記事タイプ` / `勝ち筋`

## 媒体軸(#media・任意)

| プロパティ | 型 | 用途 |
|---|---|---|
| `媒体` | select(`コラム`/`ニュース`) | 記事の公開先を出し分ける。`ニュース`→常に news エンドポイント(告知)/ `コラム`→従来どおり `GROWTH_MICROCMS_ENDPOINT` 従属(SEO 資産)。 |

- **任意プロパティ**。**未追加でも従来どおり動く**(欠落=`コラム`扱い=完全後方互換)。
- 週次モードは `媒体=ニュース` の告知案も提案する(告知版S4=確定事実のみ・日時断定禁止)。下書きモードは `媒体` で payload と公開先を分岐する。
- 追従経路と制約は設計書 `docs/superpowers/specs/2026-07-03-growth-media-axis-design.md` §3/§5 を参照。

## コラムカテゴリ上書き(#222・任意)

| プロパティ | 型 | 用途 |
|---|---|---|
| `コラムカテゴリ` | select(`start`/`rules`/`improve`/`health`/`compare`/`event`) | 下書き生成時の `payload.category` を**既定マッピングより優先**して人が上書きする(読者向けの最終分類)。 |

- **任意プロパティ**。**未追加でも従来どおり動く**(欠落耐性)。空/未設定なら `記事タイプ` からの既定マッピング(正典 `columnCategory.ts`)で解決する。
- 解決は `npm run growth:column-category -- "<記事タイプ>" "<コラムカテゴリ>"` に一本化(drafts.md は手書き表を持たない=単一ソース #222)。
- category(読者向け・回遊/SEO)と `記事タイプ`(内部計測 #C4)は**別軸で共存**(AD8)。上書きは読者向け分類だけを動かし `記事タイプ` は変えない。

## 学習ループ(#221・週次「伸ばす学習」の入力)

週次モードは `growth:existing` 出力末尾の「公開済み記事の成績サマリ(記事タイプ別)」を読み、成功が多い型を優先する。集計は**既存プロパティのみ**で行い新規追加は不要:

| プロパティ | 型 | 用途 |
|---|---|---|
| `記事タイプ` | select | 集計の軸(獲得/不安解消/資産/比較/イベント)。欠落は「タイプ未設定」に寄せる(黙って落とさない)。 |
| `公開後判定` | select | 人が決めた公開後判定(未判定/成功/様子見/要改稿)。未設定は「未判定」として数える。 |
| `成績データ` | text | `search.topQueries` から「勝ったクエリ」を抽出(空/不正でも壊れない)。 |

**欠落耐性**: いずれのプロパティも未設定・公開0本で空サマリになるだけで壊れない。集計対象は `ステータス`=`公開済み` の行のみ。

# Notion「施策提案」DB 必要プロパティ

> data source: `3503f4bc-b1c4-4927-91ce-7609a6c4e460`。基本プロパティ(施策名/カテゴリ/確度/インパクト/工数/週キー/施策ID/根拠/想定アクション/ステータス)は runbook 参照。

## 施策の仮説(改善案#5・記事S4と対称・任意)

| プロパティ | 型 | 用途 |
|---|---|---|
| `仮説` | text | この施策で何がどう良くなるか＋根拠。週次が書き、承認画面で確認。 |
| `成功指標` | text | 効いたと判断する基準と測る面(GA4/GSC/GBP/予約 等)。 |
| `検証予定日` | date | 成功指標を突き合わせる予定日。`growth:proposal-review-due` がこの日で到来判定。 |
| `検証結果` | text | 施策版 review-due が書く判定メモ候補(効いたか)。人が最終判断。 |
| `検証済み` | date | review-due が二重に拾わないための記録日(到来を1回だけ通知)。 |

- **いずれも任意プロパティ・欠落耐性**: 未追加でも週次登録・review-due は沈黙落ちせず動く(未入力は「仮説なし/検証予定なし」として扱う)。
- `growth:proposal-review-due` は `検証予定日` が来た(かつ `検証済み` 未記録の)施策を列挙し、`検証結果` 候補と `検証済み` を書いて LINE 通知する(記事の review-due と同じ流儀・純ロジック分離)。
