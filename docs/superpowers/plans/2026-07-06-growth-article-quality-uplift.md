**実装詳細(§3.1.2・過剰除去を避ける保守的実装・決定的純ロジック・LLM 非依存):**

`removeAiDisclaimer(bodyHtml)`:
1. `splitTopLevelBlocks(bodyHtml)` でトップレベルブロック配列を得る(`decorate.ts` を再利用・重複実装しない)。
2. **各ブロックの内側テキストを** `block.html.replace(/<[^>]+>/g, "").replace(/&nbsp;/g, " ")` で得て、`DISCLAIMER_MARK` を**部分一致で含むブロック**を「注記ブロック」と判定する(`draftQuality` の `plain.includes(DISCLAIMER_MARK)` と対称)。
3. 注記ブロックを**その開閉タグごと**除去する。除去は `splitTopLevelBlocks` が返す `start`/`end` オフセットを使い、注記ブロックの区間を元 HTML から取り除く(複数ある場合は**すべて除去**・オフセットのズレを避けるため後ろのブロックから前へ向かって除去するか、除去対象の区間を集めてから 1 度に組み立てる)。
4. **裸テキスト(タグ外)にマークがある場合**: `splitTopLevelBlocks` はトップレベル要素間のテキストをブロックに含めない。除去後の残りに `DISCLAIMER_MARK` を含む裸テキストが残っていたら、その行(直近の `<br>` またはブロック境界で区切られた区間)を除去する。裸テキスト除去は「マーク文字列を含む最小の行区間」に限定し、他のテキストを削らない。
5. **除去後の後始末**: 除去で生じた末尾の空ブロック(`<p></p>` や `<p>\s*</p>`)・連続する空白/改行を畳む。ただし本文中の正当な空要素・意図的な改行までは削らない保守的処理にする(除去箇所の直後に限定)。
6. **戻り値**: `{ body: 除去後HTML, removed: 1つでも除去したか }`。
7. **冪等性**: マーク不在なら `removed=false`・`body` は入力と**同一文字列**を返す(二重公開・再公開でも安全)。
8. **他段落の不変性**: 免責ブロック以外の見出し・段落・画像・リンクは一切変更しない。

**受け入れ挙動(§3.1.6):**
- 末尾 `<p>※この記事はAIが作成した下書きです。公開前に内容をご確認ください。</p>` を除去し `removed=true`・他段落を保持。
- 注記が本文中間にあっても当該ブロックだけ除去・前後を保持。
- 注記が裸テキスト(タグ無し)なら当該行を除去。
- マーク不在なら無変更 `removed=false`(冪等・入力と同一文字列)。
- 既除去本文の再適用が無変更(二重公開安全)。
- 複数の注記ブロックがある場合は全除去。
- 除去後に空ブロック・余分な空白を残さない。
- 空文字・巨大入力(数万字)でも throw しない。

**テストケース一覧(`aiDisclaimer.test.ts`):**

- 中間位置の注記ブロック除去 → 前後の段落が保持される。
- 裸テキスト(`本文</p>※この記事はAIが作成した下書きです。〜`)の行除去 → マーク行だけ消え本文は残る。

      const status = selectName(page, "ステータス") || "ステータス無し";
      const titleValue = titleText(page, "タイトル案") || "(無題)";
      const head = `- [${weekStartValue} | ${status}] ${titleValue}`;

      // 公開後判定=要改稿 の行: 「公開後判定: 要改稿」を出し、却下理由が非空ならスラッシュで続ける。

## デプロイ後の運用手順(タスクにしない・§3.1.5)

**既公開1記事の手修正(コードのマージ・デプロイ後・人間立会いで1度だけ)**:
既に公開済みの記事「市川でピックルボールができる場所と、屋内専用という選び方」には AI 免責注記が残存している。**コードの遡及修正では直さず、人間承認のもと運用で1度だけ手修正する**(公開記事の本文書き換えは取り消しづらい外向き操作のため)。

1. オーナーが対象記事の microCMS 本文を確認し、末尾の注記段落(`※この記事はAIが作成した下書きです。〜`)を特定する。
2. **人間立会いのもと**、microCMS 管理画面または承認画面の手動リッチ編集(`/api/growth/draft/edit`)で注記段落を削除して**再保存**する(手動編集は認可済み経路)。
3. 保存後、公開状態を確認する(microCMS で公開のまま本文が更新されること)。
4. 修正後の記事に注記が無いことを目視確認する。
5. 以降の新規公開は T2/T3 の除去ロジックで自動的に注記が外れる(この手動修正は既存1記事の後始末のみ)。

- この修正は本計画のコード変更(除去ロジック)がマージ・デプロイされた**後**に行う。新経路が入った後は、次の再公開で再び注記が付く余地は無い(注記は下書き生成時に付き、公開時に外れる設計に統一されるため)。
