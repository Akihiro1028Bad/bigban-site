# 成長数値目標と「目標との距離」設計

> 起案: 2026-09-25（週次対話でのオーナー依頼「目標を設定し、それに向けた施策を毎週提案してほしい」）
> 関連正典: `docs/superpowers/specs/2026-08-05-growth-copilot-design.md` / `docs/growth/analysis-contract.md` / `docs/reviews/2026-08-12-japan-no1-site-review.md`
> 目標値の台帳: `docs/growth/goals.md`（本設計の運用対象）

## 1. 背景と問題

現状の目標体系は3層あるが、真ん中が欠けている。

1. **北極星（定性）**: 「日本一のピックルボール施設・日本一の HYROX トレーニングクラブ」。月次の日本一スコアカードが外部比較で距離を測る。達成条件の数値はない。
2. **（欠落）数値目標**: 「いつまでに・どの指標を・いくつにするか」が未定義。
3. **施策単位の中間指標**: 大カウンタ5つで2〜4週判定。「改善したか」は分かるが「**目標に間に合うペースか**」は判定できない。

この欠落により、週次の施策採否が「良さそうな順」になり、最も遅れているボトルネックに資源を寄せる判断ができない。

## 2. 設計

### 2-1. 目標台帳（`docs/growth/goals.md`）

- 指標 G1〜G6・現状値・目標値・必要ペース（週あたり）を1ファイルに置く。ルーチンは**読むだけ**。値の確定・変更は人間の PR。
- 期限は開業1周年（2027-04-17）。目標値は 2026-09-24 実測を土台にした**仮案**で、オーナー確定をもって有効になる（未確定の間も「距離」の出力は仮案値で行い、仮である旨を1行付す）。
- 指標の選定基準: (a) 週次で台帳・GA4 から機械的に測れる (b) 施設経済（キャパ稼働×単価×リピート）に直結する (c) ピックルと HYROX を対等にカバーする。

### 2-2. 週次ドライバーの変更

1. 準備で `docs/growth/goals.md` を読む（無ければ「未作成」と補足に1行）。
2. 出力の冒頭判断部に **「■ 目標との距離」ブロック（最大7行）** を追加: G1〜G6 の実測 / 目標ペース比 / オントラック・遅れ・先行の3値判定。2週連続遅れの指標を**最遅指標**として1行で明示する。
3. **施策提案の紐付けを必須化**: Step 2-4 の新提案は「効く目標指標（G1〜G6のどれか）」を根拠欄に必ず書く。空き枠の補充は**最遅指標に効く案を最優先**で検討する。
4. **レーン満床の週も手ぶらで帰らない**: WIP 上限 2 は変えない（v1 の死因=提案だけ増える仕組み、を守る）。ただし満床の週は「■ 今週の提案」に**次枠候補1行**（最遅指標向け・起票はしない）を必ず書き、枠が空いた週にそれを第一候補として起票する。

### 2-3. 月次ストラテジストの変更

- M-1 に「目標との距離の月次確定」を追加: G1〜G6 の月次値・累積ペース差・目標値見直し提案（必要時のみ）。日本一スコアカード（外部比較）と対になる**内部スコア**という位置付け。

### 2-4. 変えないこと

- WIP 上限 2 / 大カウンタ5つ / 判定ウィンドウ / 48時間確定 / 個人情報の扱い — すべて既存の共通契約のまま。
- 目標は施策の**優先順位付け**に使い、施策の勝ち負け判定基準には使わない（判定は従来どおり施策ごとの事前閾値）。

数値はいずれも**オーナーが確定・修正する前提の仮案**。強気/弱気の調整はこの表の根拠ごと直すこと。

## 4. ロールアウト

1. 本 PR: `goals.md`（仮案）+ 本設計 + `weekly-driver.md` の出力・提案ルール改訂。マージした翌週の木曜から「目標との距離」が配信される。
2. オーナーが `goals.md` の仮案を確定（値を直す場合も PR で）。
3. 月次ストラテジスト（次回 = 2026-10-01 第1木曜）で初回の月次確定を実施。
4. 3ヶ月（2026-12月末）時点で、目標起点の施策が採用・検証されているかを月次が棚卸しする。機能していなければこの仕組み自体の縮小を進言する（数字だけ増える仕組みは死なせる）。
