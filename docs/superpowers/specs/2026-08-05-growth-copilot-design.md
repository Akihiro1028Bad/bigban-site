# グロースコパイロット 設計書（2026-08-05）

> 旧ヘッドレスグロースループ全廃（PR #358 / docs/reviews/2026-08-04-growth-and-site-review.md）を受けた後継。
> 分析・施策提案・記事企画を「クラウドルーチン（準備）＋対話（判断・実行）」の二層で回す。

## 1. 目的と原則

- **対象施設の前提**: THE PICKLE BANG THEORY は**ピックルボール施設であると同時に HYROX 公式ジム**（認定 2026-08-03・関吉大亮選手が契約選手兼メインコーチ）。分析・提案・記事企画は**両事業を対等に扱う**。
- **目的**: サイトと施設の成長施策（デザイン変更・バナー・ポップアップ・ページ・記事・ニュース）を、定期分析に基づいて提案し、**検証まで一周させる**。
- **v1 の死因への回答**: v1 の施策提案 DB は検証結果 0 件で死んだ。本設計は「提案を出す仕組み」ではなく「**検証を駆動する仕組み**」を中心に置く。
- **不変の原則**（旧システムから継承）:
  - 本番公開・PR マージ・施策採否は必ず人間。AI の自律判断で本番は変わらない
  - 記事の執筆・公開は CLAUDE.md「記事の対話運用」に従う（対話・DRAFT 投入・人間公開）
  - Labola 台帳の個人情報は runbook「台帳の個人情報の扱い」に従う（会話は可・成果物に残さない）

## 2. 設計を縛る事実（2026-08-04 実測）

1. **流入規模**: reservation_click 約750/週・/reserve PV 約780/週・オーガニック約830セッション/週・実予約60〜100件/週。2週間で検出できる変化は ±10〜15% が下限。
   → 成功指標は**大カウンタ5つに限定**（reservation_click / reserve_entry_click / 実予約件数 / 対象ページPV / **HYROX 枠の実予約件数**（予約台帳 `コート='HYROX'`。2026-08-05 追加））。判定ウィンドウ最短2週。**同時実験 WIP=2**（別指標・別ページ面に限る）。
   **HYROX 枠は母数が小さい**（認定 2026-08-03 以降のデータのみ）。週平均が10件未満のあいだは**判定ウィンドウを最短4週**とし、分母10未満の比率を根拠にしない。
2. **実行基盤**: claude.ai のクラウドルーチン（cron）。Mac の起動に依存せず、結果はスマホの claude.ai アプリに届く。
3. **既存資産**: Notion「施策提案」DB（スキーマ流用）・「記事ネタ案」DB・Labola 台帳 / scripts/analytics/query.mjs / draft PR → Vercel プレビュー自動生成 / 画像生成 CLI（ローカル）。

## 3. 全体構成 — 3ループ + 実験レーン

```
日次ウォッチ   (毎朝 07:30・クラウド)  異常検知のみ。平常時は完全沈黙
週次ドライバー (木曜 07:00・クラウド)  数字→レーン判定→空き枠補充→3週先読み→アクション≤2
月次ストラテジスト (第1木曜・週次を+30分拡張) 大玉のみ: ページ/IA・市場ウォッチ・記事月間計画・LLM-SEO・プレイブック更新

実験レーン(常時): [施策A 計測中] [施策B 計測中]   ← WIP 上限 2
```

- 施策提案は月次バッチではなく**カンバン方式**: 週次が「判定日到来→判定→枠が空く→新提案1〜2案で補充」を同一セッション内で一周させる。
- カレンダートリガー（季節・イベントの2〜3週前）は WIP と無関係に割り込み提案できる。

## 4. 施策台帳 v2（Notion「施策提案」DB を拡張）

置き場所は Notion 既存 DB（af87618b-81e9-4943-a851-9b4124185114）。理由: ルーチン（クラウド）と対話（ローカル）の両方から MCP で読み書きでき、オーナーがスマホで見られ、既存スキーマ（仮説/成功指標/検証予定日/検証メモ/検証結果）を流用できる。

**追加4列**（2026-08-05 適用済み。実装リンクは既存の `成果物リンク`(url) を流用するため新設しない）:

| 列 | 型 | 内容 |
|---|---|---|
| 状態 | select | 提案中 / 採用 / 計測中 / 判定待ち / 勝ち / 負け / 引き分け / 却下 / 撤去候補 |
| 種別 | select | バナー / ポップアップ / セクション / ページ / 記事 / ニュース / その他 |
| ベースライン値 | text | 実装マージ検知時に AI が対象指標の直近2週実測を自動記録 |
| 学び | text | 判定確定時の1行。プレイブックの原料 |

v1 由来の既存列（ステータス / カテゴリ / 検証結果 等）は既存行が値を持つため変更しない。v2 のライフサイクルは新設の `状態`・`種別` 列だけを正とし、旧列は読み取り参考に留める。

**ライフサイクルと運転ルール**:

```
提案中 ─人間─▶ 採用 ─▶ 計測中 ─検証日─▶ 判定待ち ─▶ 勝ち/負け/引き分け ─▶ 学び記録
   └─人間─▶ 却下(理由1行)                │
                            判定待ち2週間放置(催促2回) ─▶ 撤去候補
```

- 検証日到来時、週次ドライバーが**ベースライン vs 実測を並べ判定案まで作る**。人間は「同意/覆す」のみ。
- **AI 判定は48時間 veto 方式で自動確定**（異議がなければ採用）。人間必須にすると v1 と同じ墓場になるため。**確定処理の実行主体は日次ウォッチ**（週次は週1回しか動かず48時間を測れないため。2026-08-05 レビューで確定）。
- 判定待ち放置2週間で自動的に撤去候補へ（なんとなく残るバナーの構造的禁止）。
- **撤去の実行主体**: 負け/撤去候補が確定したら、週次ドライバーが revert の draft PR（`growth/revert-<slug>`）を作成し、マージは人間が行う（2026-08-05 レビューで確定）。
- 成功指標は §2 の大カウンタ5つから選び、**イベント名・閾値・検証日を提案時に確定**する。
- **新提案には根拠の紐付けを必須**にする（分析バッテリー第N項 / リサーチ RN のどれが起点か。§5 参照）。根拠を紐付けられない提案は起票しない。

## 5. 週次ドライバー仕様（木曜 07:00・クラウドルーチン）

プロンプト正本: `docs/growth/routines/weekly-driver.md`。

**設計原則（2026-08-05 改訂）: 分析と発見は最大化し、判断は最小化する。**
「どんな小さなことも見逃さない」と「オーナーの判断負荷を増やさない」は両立させる必要があるため、
メッセージを**冒頭の判断部**（数字→レーン→提案→記事ネタ→3週先読み→アクション≤2）と**後半の詳細部**（詳細分析・リサーチ・気づき）に分離する。
**冒頭の判断部だけ読めば意思決定が完結する**ことを原則とし、後半は読み流し可とする。

届くメッセージの構成:
1. 数字ダイジェスト: query.mjs 7日比較（GA4/GSC）+ Labola 台帳集計（Notion）
2. レーン: 判定日到来分の判定材料+判定案 / 空き枠があれば新施策1〜2案（**根拠の紐付け必須**）
3. **デザイン系施策は実装済みで届く**: ブランチ `growth/<slug>` に実装し draft PR + Vercel プレビュー URL 付き
4. カレンダー3週先読み（`docs/growth/seasonal.md` の季節表 + 公式発表を確認できた HYROX 大会日程）
5. 今週のアクション最大2個
6. **詳細分析（分析バッテリー11項目）** — 後半・読み流し可
7. **リサーチ（リサーチバッテリー R1〜R5）** — 後半・読み流し可
8. **気づき** — 後半・読み流し可

**分析バッテリー（11項目・毎週全部実行・省略禁止。2026-08-05 新設）**:
予約ペース(4週トレンド) / 曜日×時間帯の谷 / Labola 公開カレンダー実測 / **HYROX 事業**(枠稼働・/hyrox PV・平均単価・構成比) /
予約ファネル段間通過率 / コホート・リピート / 離反予備軍 / 集中度 / SEO 精査(取りこぼし・4〜10位・タイトル改善・新出クエリ) /
チャネル(Referral・AI Assistant) / 外れ値スキャン(前週比 ±30% 超を機械的に全列挙)。
各項目は「実測→解釈→施策の種」を各1行（1項目 最大3行）。**取得できない項目は「取得不可」と明記し、黙って落とさない。**
`query.mjs` は CTAイベント・ファネル・GSC を今期分しか出力しないため、`--days 14` を併走させ **14日窓 − 7日窓**で前週の絶対値を復元する。

**リサーチバッテリー（毎週・合計15行以内。2026-08-05 新設）**:
R1 Notion「Morning Business Brief」(`collection://46e2f82a-f465-44be-986e-2b12208abeb2`) の直近7日分を**最初に収穫**して二重リサーチを避ける /
R2 国内ピックルボール / R3 世界のピックルボール（会員制度・料金モデル・イベント形式）/ R4 HYROX・ハイブリッドフィットネス / R5 **異業種転用（最低1件必須）**。
事実（出典・日付）と推測を区別し、**各発見に「当施設への転用案」を1行必ず付す**。転用案が書けない発見は載せない。

**気づきセクション（2026-08-05 新設）**:
提案化に至らない小さな発見を**閾値なしで最大10行**記録する受け皿。有望なものに `【来週の提案候補】` を付す。
**オーナーの採否は不要**（読み流し可）で、**気づきをアクションに昇格させない**（今週のアクションは常に最大2個）。

**分量規律**: 全体 **140行以内**（60行から拡大。月次パートは別枠 +30行）。内訳は判断部30・詳細分析35・リサーチ15・気づき10・補足10。
守れないときは**後半から削り、冒頭の判断部は削らない**。

**無人実装のガードレール**:
- 触れてよい面の許可リスト: バナー / 既存セクションの文言・表示 / 既存コンポーネントの variant。**新規ページ・依存追加・env・API・公開系・microCMS・分析スクリプト（`scripts/analytics/**`）は禁止**
- diff 150 行以内 / CI green 必須 / **draft PR のまま。自分でマージしない**
- ブランチ prefix `growth/`、PR タイトル prefix `proposal:`
- 記事・ニュースは brief（狙いクエリ・構成案・成功指標・根拠の紐付け）としてネタ案 DB へ書き、執筆は対話で行う

## 9. 実行基盤（クラウドルーチン）

- claude.ai のルーチン（scheduled cloud agents）で3本を cron 登録。結果は claude.ai（スマホ含む）にメッセージで届く。
- リポジトリはクラウドがclone。GA4/GSC は**クラウド環境の env secrets** に以下5つを設定して query.mjs を動かす:
  `GROWTH_GOOGLE_CLIENT_ID / GROWTH_GOOGLE_CLIENT_SECRET / GROWTH_GOOGLE_REFRESH_TOKEN / GROWTH_GA4_PROPERTY_ID / GROWTH_GSC_SITE_URL`
  （読み取り専用スコープの分析用トークン。セットアップ時にオーナー自身が claude.ai の環境設定へ登録する — この登録作業をもって了解とする）
- Notion はコネクタ経由（クラウドで動作）。microCMS・画像生成 CLI・LINE はローカル専用のまま（対話作業でのみ使用）。
- **GitHub アカウント**: クラウドルーチンが作る draft PR は GitHub App／オーナー認可でよい（オーナー決定 2026-08-05）。`ttmakhr1028ai-art` 規約は**ローカル対話での push にのみ適用**。CLAUDE.md に例外として明記する。
- フォールバック: クラウドで GA4/GSC が使えない場合、数字なし版ダイジェスト（台帳+レーンのみ）を配信し、その旨を明記する（沈黙させない）。
